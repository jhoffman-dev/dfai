Tags

A tag is plain text in the note — #idea — read the same way when it is drawn, counted, clicked and renamed.

Write one

TypeIs
#ideaThe tag idea.
#tag me#A tag of several words, closed by a # later on the same line, as Bear writes it.
#area/topicA nested tag: topic under area. Nest as deep as you like.
# TitleA heading, not a tag — the space makes the difference.
tags: [idea, area/topic]Tags in the note's frontmatter count too, with or without the #.
  • A tag needs a letter in it: #1 stays a number. It is words of letters, numbers, _ or -.
  • A tag, and each part and word of it, can't start or end with _: #my_tag is fine, #_draft_ is no tag.
  • A one-letter word doesn't close a tag of several words, because its # is C# or F#: #todo fix the F# build is the tag todo.
  • The # must start the word: C#, issue#12 and a link's #heading are not tags, and neither is anything in code. Write \# to keep a # as plain text.
  • #Idea and #idea are one tag, shown as it was first spelled.

Suggestions as you type

  • After # and a letter, a list offers your tags with how often each is used. The tag you typed comes first — the one of that name, or Create #… if it is new — then longer and nested tags that match.
  • ↓ ↑ to choose another, Return or Tab to write it, Esc to close the list. For a new single word you can just keep typing.

The Tags page

  • Tags are highlighted in notes and on feed cards; click one to open it on the Tags page. Tags is also in the sidebar, under Graph.
  • The page lists every tag as a tree, nested tags under their parent, each with its count of uses. A parent's count includes its children's. Archived notes aren't counted. Sort by Name or Frequency.
  • Choose a tag to see the notes that use it, or any tag under it, with how many times; click one to open it.
  • There is nothing to clean up: a tag no note uses any more disappears from the list on its own.

Rename or merge

  • Choose a tag, then Rename. Type the New name and Preview lists the files that will change and how many uses in each. The button, now Rename n uses, changes it in every note, in the text and in tags: alike, touching nothing else in the file.
  • Tags nested under it follow: renaming #para to #area makes #para/resource into #area/resource.
  • If the new name is already a tag, the button reads Merge into #… and the two become one tag. A tag used only as the parent of others counts: renaming to #beta when #beta/y is written merges too.
  • Renaming to the same name with other capitals makes every use spelled the same way.
  • A rename reaches archived notes too, though the page doesn't count them.
  • A tag can't be moved inside itself (#para to #para/old), and a name that breaks the rules above is refused with the reason.
  • A new name of several words can't end in a one-letter word, since its closing # would read as C# does. plan a is refused: “A tag of several words can’t end in a one-letter word: #plan a# would read back as a shorter tag.”
  • Where the new name, closed with its #, would run into what follows it — #idea_ or #idea#x renamed to my tag — that note keeps the old name. The preview lists them after “1 note keeps #idea:”, each with why, such as “#my tag# can’t be written right before “_” and still read back as that tag.”
  • If another rename, in the app or over the API, has just made the new name a tag, the rename is refused at the last moment rather than merging unasked: “#… is in use already, so the rename would merge into it.” Preview again: the button will then read Merge into #….
  • A note with typing not yet saved is left alone; the message after the rename names it, so you can rename again once it is saved.
Filtering by tag. An DFAI query finds notes by tag, written in the text or in tags: alike: Tag in the builder, or tag = #idea as text, which also finds the tags nested under it. A type's own view filters only by a frontmatter tags: property, like any other property.
