Tasks (GTD) and daily notes

Tasks follow GTD: a task is in exactly one of eight statuses, from Inbox to Archive. Capture lands in the Inbox; deciding what a task is moves it on.

StatusWhat it means
InboxCaptured, not yet decided on. Every new task starts here.
BacklogWorth doing, not now — so Next Action stays short.
Next ActionThe next thing to do, ready to be picked up.
In ProgressStarted; it may take days.
WaitingWaiting on someone or something. Saying who, in Waiting on, is optional.
SomedayAn idea kept for later.
LongtermReal, but a long way off.
ArchiveFinished. Ticking a task puts it here, with the day.

A task's properties

  • Waiting on says who a task waits on, and is always optional. Waiting is a status like any other: drag a task there on a board, pick it in the properties panel, or have an automation or Claude set it, and nothing asks who. A status written waiting or [waiting] is Waiting too, and is saved as waiting.
  • Contexts — where it can be done (@phone, @errands); add your own options in Edit type.
  • Defer until — a day before which it stays out of Next actions. Due — when it must be done.
  • Estimate (minutes) — what timeblocks are measured against — Source — where it came from — and Project, filing it under a project or an area.
  • Completed is written for you: the day a task was finished.

Tick it off

  • Every task shows a checkbox in tables, lists, boards, galleries and feeds. Ticking moves it to Archive and writes today as Completed; unticking puts back the status it had and takes the day away. (Unticking after a restart, when DFAI no longer remembers, puts it at Next Action.)
  • A task made already in Archive — from a board's Archive column, say — is given today as Completed too.
  • Recurring tasks roll on to their next date when ticked, or when dragged into Archive on a board, and go back to Next Action.

Checklists and progress

A task that takes days stays In Progress, and its steps are a checklist in its text — - [ ] lines, typed or made with / → Task list.

  • Progress is the share of boxes ticked: a bar and a percentage on its card on a board, its row in a list, and under its name in a table. 2 of 5 ticked is 40%; it reads 100% only when every box is ticked. Nested boxes and boxes in a quote count; a note with no box shows no bar.
  • Ask for it in a query: FROM task WHERE progress >= 50 SORT BY progress DESC, or a project's with project.progress. It is worked out from the file whenever the note is saved, so rebuilding the index gives the same numbers. A type with a Progress property of its own keeps that instead, and draws no bar.

Make a line its own task

When a step grows into a task of its own, click into its line and press Make task after its words, or ⇧⌘↩.

  • A task named by the line is made in Tasks/<year>/<month>, its home folder, in the Inbox — or Archive, with today as Completed, if the line was ticked. Its Source links back to the line, and its Project is the note's project (or the note itself, when it is a project or an area).
  • Nothing the line said is lost. A line of plain words becomes a link to the task that reads the same — Order chairs stays Order chairs, even when the file had to be named differently. A line with a link, a tag, code or bold in it keeps all of that after the new link, and the new task starts with the line in its text too, so the person it mentions and its tags are linked from the task as well.
  • The line keeps its box, and the lines under it stay. The list it is in is written again, so a list written with * or numbers comes back with - — the same as typing in it would. The rest of the note is untouched.
  • A line that is a task already — it starts with a link to one — isn't made a task again: That line is the task “Order chairs” already. A very long line's task gets a name cut short to fit a file name.
  • The box at the bottom right says “Order chairs” is a task now. with Open and Undo; it goes by itself after 5 seconds, and waits while the pointer or the focus is on it. Undo puts the line back exactly as it was and sends the task to the Trash, in one step — unless either changed since, which a line under the page's bar says until you dismiss it. So does a line that could not be made a task. ⌘Z in the note doesn't take a promotion back: a note read again from its file is never a step to undo.
  • Typing in the note is saved first. A line that is empty can't be made a task, and a template's lines aren't offered.

The GTD views

  • Inbox — tasks still to decide on. Next actions — what can be done now, leaving out anything deferred to a later day until that day comes. Waiting — grouped by who it waits on. Someday and Longterm — a board of the two; move a card between them with its Move to….
  • They are ordinary query views in .atlas/views, added when your tasks move to GTD. A view of yours with the same name is never replaced.

Act on tasks from a query view

In a saved query view that lists tasks alone — FROM task, as every GTD view does — each row, in a list, a table or on a board, does what a Today row does, and writes the same change to the file:

  • The box finishes the task: Archive, with today as Completed. A repeating task rolls on to its next day instead — its recurrence may be written as a list of one, [every week]; a list of two rules is no rule, so that task just finishes, and a task chosen for today stops being chosen. Untick a finished one and it goes back to Next Action.
  • Move to… sets any of the eight statuses. Archive there is the same as ticking the box.
  • Today chooses the task for today, and is highlighted while it is chosen; press it again to take it off. It shows where the Task type keeps a Chosen for date, and not on a task whose Chosen for holds words of your own.
  • The row changes the moment you act, and takes nothing else until the file is read back. The box at the bottom right says what changed, with Undo.
  • A change is made only while the task still says what its row showed. If the file changed since — edited elsewhere — nothing is written: the row says This task has changed since the page read it, with Try again. Try again makes the same change, on the day you press it, while the row still shows the task as it did; once the view shows the task as it changed, Try again lets the message go and does nothing, so a repeating task ticked elsewhere meanwhile is never rolled on twice. A write that fails is said on the row the same way.
  • Everything is reachable with Tab: Space ticks the box, and Enter presses Today or opens Move to…, whose statuses the arrow keys walk. The focus stays on the box while the tick is written, and when the task leaves the view — ticked out of Next actions — it moves to the row under it, or the one above when it was the last.
  • A view of several types (FROM task, project), the Query page and a query block in a note stay look-only. A board's cards are moved with Move to…, not dragged.

Today

Today at the top of the sidebar — or ⌘K → Today — is the morning page: what needs you today, on one screen. It shows once your vault has tasks, and needs no saved view. Each heading carries its count, and a task is listed once, in the first section that claims it — so an In Progress task due yesterday is under Overdue only, and the counts add up.

  • Chosen for today — what you picked to do today, at the top, whatever its status: an In Progress task you chose is here, not under In progress. Press Today on any row to choose it, and press it again — it's highlighted while chosen — to take it off. The earliest due first, then by name.
  • Carried over — what you chose on an earlier day and didn't finish. It shows only when there's something in it. Keep chooses the task for today; Drop lets the choice go, and the task goes back to its usual section. Each says the day it was chosen for.
  • Overdue — still open and due before today, the earliest first. Due today — due today. Both are only said of open work: Someday and Longterm promise no day.
  • Back from deferral — tasks whose Defer until is today, in any status but Archive (Someday and Longterm included): what you put off until now. An Inbox, Backlog, Someday or Longterm task whose day has already passed is listed here too — nothing else on the page would show it — and stays until you deal with it or put it off again. Each says the day it was deferred until.
  • In progress — what is under way.
  • Next actions — grouped by project, each project's name opening it, with No project last.
  • Waiting — grouped by who it waits on, the longest wait first, each with its days: Quote from Larkspur — 4 days since last change. The days are counted from the task's file last changing, in whole days — DFAI keeps no “waiting since”, so any edit to the task starts its count again.

A task deferred to a later day is in no section until that day. Above the sections: the Inbox with its count, Stalled projects — active projects with nothing next, which opens the weekly review — and Open today's note (⇧⌘D). The day is your Mac's own date, and turns over at midnight where you are: a page left open overnight shows the new day within a minute, or as soon as you look at the window again.

A choice is for one day. Choosing a task writes the day into its note — focus: 2026-10-28, shown as Chosen for — and taking it off removes the line again, so the note goes back to exactly what it was. Nothing is written at midnight: the next morning, yesterday's choices are under Carried over until you keep or drop them. Ticking a task done ends its choice. That includes a repeating task that rolls on to its next date, so it doesn't sit under Chosen looking as if the tick did nothing; Undo puts the day back. A task chosen for a later day says Chosen for 2026-11-02 in its usual section; Today moves the choice to today. focus = @today in a query lists what's chosen today. The Task type gets Chosen for by itself the first time the vault opens. If your Task type already has a property called focus of another kind, or you delete it, DFAI leaves it alone and doesn't add it back, and Today offers no choosing at all: no Today button, no Chosen for today or Carried over. A task whose focus holds something other than one day (words, a link, several dates) is never treated as chosen, and choosing never writes over it.

Each row shows the task's project, contexts and due date, opens from its name, and has:

  • Today — choose the task for today, or take it off. On a row under Carried over, Keep and Drop instead.
  • A done box — ticks the task as a type's view does: finished and dated today, or a repeating task rolled on to its next date.
  • Move to… any other status, Waiting included — it never asks who.
  • +1d and +7d — defer until tomorrow, or for a week. The task leaves the page and comes back that day.

From the keyboard, with a row's done box focused (Tab to it, or click it): J K or ↓ ↑ move to the row below or above, across sections, and the focused row is tinted; Return opens the note; X ticks it done; T presses its Today (Keep, under Carried over); D defers it a day, as +1d; N W S move it to Next Action, Waiting or Someday; M opens Move to…; and U (or ⌘Z) takes back the last change, the row it brings back taking the focus again — once the change before it has been read back, so it never takes back an older one. When a row leaves the page, or moves to another section — chosen for today, say — the focus goes on to the row that was next. A strip above the sections lists the keys. They are letters inside a field, a menu or a dialog, never act with ⌘, ⌃ or ⌥ held (but ⌘Z), and wait while a row's controls do.

The page updates in place. A row acts on what it showed you: if the task has changed since the page read it — ticked in another view, say — the action is refused and says so, and nothing is written. A row you have just acted on takes no other action until the page has caught up. The box at the bottom right offers Undo for the last thing you did — it puts back exactly what the action changed, as it was written, and refuses if the task has been edited since. Everything is reachable with Tab; after a row leaves, focus lands on the row that was under it, so Space ticks down a list.

If your vault has a saved view titled Today, the sidebar still shows one Today row — the page — and the page links to your view from its top right: Open the “Today” view.

The weekly review

Weekly review in the sidebar, under the Inbox — or ⌘K → Weekly review — puts GTD's questions of the week on one page:

  • Inbox — how many wait in the Inbox, counted as the sidebar counts them: notes and tasks to process and proposals to answer — and Open the Inbox.
  • Waiting for more than 7 days — Waiting tasks nobody has touched in over a week, the longest first, with who they wait on — a linked person or a name you typed: Quote from Larkspur — On Mara Quill.
  • Active projects with no next action — a project whose status is active with no task filed under it at Next Action or In Progress.
  • Overdue — tasks due before today that are still open: Inbox, Backlog, Next Action, In Progress or Waiting. Someday and Longterm promise no day, so they are never overdue.
  • Someday and Longterm, untouched for 30 days — ideas left alone for over a month, the oldest first.

“Untouched” means the file hasn't changed: DFAI keeps no “waiting since”, so any edit — yours, or the review's own — counts as a look. A task deferred to a later day is in no section until that day, as it is out of Next actions. Finished and archived notes are never listed. Whether a project has a next action is asked of the whole vault, so it is right even in a vault too big for the review to read every task.

Each item opens from its name, and has quick actions. Acting on one takes it out of its section:

  • Move to… another status — only ones that take it out of its section. A waiting task or an old idea can go to any status but Archive; a late task only to Someday or Longterm, since in any other open status it would still be late (or Defer it, or Archive it). A project can go to any of its type's statuses — paused, say.
  • Defer a task a week: Defer until becomes seven days from today, and the task comes back then.
  • Archive a task to finish it, as ticking it does: today becomes Completed, or a repeating task rolls on to its next date, back at Next Action. A project goes into the Archive, as its Archive command does.

Move your tasks to GTD

A vault whose tasks use other statuses — this project's own backlog, next, doing, review, done, say — is offered the move on the Inbox page: “Tasks follow GTD's eight statuses, from Inbox to Archive. 85 tasks would move to them.”

  1. Press Preview the move. Nothing is written yet.
  2. Check the mapping. Each status your tasks hold is listed with how many tasks hold it and what it becomes: backlog → Backlog, next → Next Action, doing and review → In Progress, done → Archive, anything else → Inbox. Change any of them from its menu. A task the mapping sends to Waiting goes there whether or not Waiting on names anyone.
  3. Read the rest: what changes in the Task type (its status becomes the eight; the GTD properties it lacks are added, and properties you added stay), views and automations rewritten (Roadmap: done → archive), any listed for you to change by hand — a filter like status contains “do” that no one status can stand for, status != review (review and doing both become In Progress, so leaving it out would leave out doing too), a status nobody knew, a query or automation over tasks and another type (a project's done is not a task's), or a SQL view — the GTD views to be added, and every task, old status → new. A finished task is given the day its file last changed as Completed.
  4. Press Move N tasks. Only the files in the preview are written, each in its status and Completed alone — the rest of every file stays byte for byte. A task with unsaved typing in DFAI is left as it is, and said so.
  • Undo the move to GTD is offered on the Inbox page for a week after the move, or until you press Dismiss beside it; then it is gone for good, after a restart and on your other Mac too. Moving more tasks later offers it again, for that later move alone: its Undo never takes back a move whose undo you dismissed or that finished before it.
  • Undo the move to GTD puts back each file's properties exactly as they were, and takes away the views it added; a file nobody touched since is back byte for byte. A file whose properties changed since the move is left as it is, and said so in Activity; one whose text alone changed gets its properties back and keeps the new text.
  • The move and its undo are each a line in Activity, with every file left alone and why. Nothing about it is silent.
  • If the move stops partway — the Mac sleeps, a disk refuses a file — open the Inbox again: the preview lists only what is left, and one undo covers both runs — keeping anything you changed in between. Running it again when nothing is left changes nothing, and once the move is done the Inbox no longer reads your tasks to check — unless a file was left or a GTD view is missing.
  • The record undo works from is kept in .atlas/migrations, so it syncs and works from either Mac.

Today's note

  • Today's note ⇧⌘D — or + beside the vault's name → Today's note — opens the day's note, making it if needed. It is named by the date, in its year's folder — Daily/2026/2026-10-12.md — whichever note you're on. One made at the top of the vault before is still found and opened.
  • A new one starts from your Daily template. With none, it starts as a note of the Daily type that starts with the day: Due and overdue and Next actions, each a live query block, then the headings What happened and What is next. The two blocks need your Task type on GTD's eight statuses, with Due and Defer until as dates (as the built-in Task type has them); a vault whose Task type keeps statuses of its own, or that has no Task type yet, or a second type spelt Task besides it, gets the two headings alone, never a block that can't run. A Daily template that makes a task is held to the task rules as any new task is — one made already in Archive is dated.
  • Due and overdue lists open tasks due on the note's day or before it, most overdue first; Next actions lists the next actions in play that day and not already due. A task is in one or the other, as on the Today page, and a task deferred past the day is in neither. Someday, Longterm and finished work never are. The blocks are queries and follow the query language's rules, so a task with an unusual value can differ from the Today page for now: words in a date field (due: TBD), a type written with capitals (type: Task), or two values in a field that holds one (due: [2026-11-30, 2026-10-01]).
  • The blocks are live: tick a task, change its status or its due date, and the note shows it — the file isn't rewritten, so it holds no copy to go stale. Each block names the note's own date — due <= 2026-10-12 — rather than @today, so last Tuesday's note still shows last Tuesday's day. The day is your Mac's own date, the one the Today page uses. Edit query on a block changes it for that note alone.
  • Your own Daily template always wins: DFAI never adds the blocks to it, or to a note that's already there. To have them in your template, copy them from a new note into it.
  • Daily notes you already have — the Notion import writes them as 2026-10-12.md at the top, type: daily — are opened as they are: never made again, numbered or rewritten.
  • Daily is a built-in type. A vault without it is offered it on the Inbox page; until you add it, daily notes still open and say type: daily. Once added, the Daily type's own page lists every day.

Quick capture from any app

  • Quick capture ⇧⌘N inside DFAI: type a line and it becomes a task in the Inbox, without leaving what you're doing.
  • From any app, press ⌃⌥N. DFAI comes forward — out of the Dock if it was minimised, onto the Space you're on if it was on another — with quick capture open and ready to type in. Return saves it to the Inbox; Esc puts capture away, and ⌘Tab takes you back.
  • No vault open? Nothing is captured, and DFAI says so: “Quick capture needs a vault: open one, and what you capture lands in its Inbox.”
  • With Settings or search up, the press brings DFAI forward and opens nothing over them — close them first, as with ⇧⌘N.
  • Change it in Settings (⌘,) → Quick capture from anywhere: Change…, then press the new keys — hold two of ⌘, ⌥ and ⌃ with a letter, digit, function key (F1–F20) or Space. One alone is refused: a shortcut from any app reaches DFAI first, so ⌘C would stop copying everywhere and ⌥E typing é. So are macOS's own, such as ⌃⌘Q (Lock Screen) and ⌥⌘Esc (Force Quit). Turn off stops it; Use ⌃⌥N puts the default back. It's set for each Mac on its own.
  • If macOS won't give DFAI the keys, Settings says “— not working” beside them, with why, and the shortcut you had before keeps working: choose others. macOS may also let two apps share a shortcut, and DFAI can't always tell — if a press opens another app, or nothing, choose other keys.
  • It works while DFAI is running. Closing DFAI's window quits it, and then nothing is listening.
  • Inside DFAI, ⌥⌘N, and your capture-from-anywhere keys (⌃⌥N to start with), open capture too. One difference from ⇧⌘N: ⌥⌘N does nothing while a palette, a dialog or the peek is up, where ⇧⌘N still opens capture. With no vault open, none of them opens it: DFAI says it needs a vault first.
  • Today in the sidebar is a view, and Inbox the Inbox page, which lists everything in the Inbox folder, every meeting not yet filed, and every task still at Inbox; their counts update as you work.

Capture from Slack

Save a Slack message — and its thread — as a note or a task in your Inbox. There are three ways in, and they all land the same way: a message saved by two of them is still one note.

Three ways to save from Slack:

  1. In Slack, through n8n. A Slack shortcut or emoji sends the message to DFAI. The steps are in tools/n8n on GitHub (the README, “Slack messages into DFAI”).
  2. Paste a link into DFAI. Copy the message's link in Slack and paste it into DFAI. See Paste a Slack link below.
  3. Ask Claude. In Claude Code or Claude Desktop, with both its Slack connector and the DFAI MCP server connected, say “save this thread to my notes” or “make a task from what Mara asked in #larkspur-payroll”. Claude reads the message in Slack and hands it to DFAI with atlas_capture, with its link. It picks a task when you want to act on it and a note when you want to keep it, and saves only what it read. Asking twice makes nothing new; Claude is told which note already holds it. A message without its Slack link is refused. (Claude in DFAI's own chat can't read Slack, so it can't save from there yet.)

What follows is what DFAI does with a message when it arrives, whichever way it came.

  • It lands in Inbox/Captures/, named after the message's first line (or the title it was sent with) and a short tag for the message — Send the renewal (slack 2db9a3ee76a9e132).md — and waits in the Inbox like anything captured. A task starts at the status Inbox; a note is a plain note.
  • The note says where it came from: Source is the message's Slack link, with Author, Channel and when it was sent. The message is a quote at the top — who wrote it, when, an Open in Slack link, then the words — and each reply in the thread is a quote of its own under Thread, with its author and time. Every message has a block id, so you can link to one reply: [[Send the Larkspur renewal#^r1793136300-000200]]. Shared files are listed under Attachments as links; DFAI never downloads them.
  • Who wrote it. When the author's email is on a Person note — Email or Other emails — the author is a link to that person. DFAI never links by Slack display name alone; someone it doesn't know is written by name.
  • Slack's bold, italics, strikethrough, code, links and @mentions come across as they look in Slack; emoji stay as :tada:. Anything else in a message is kept as plain words: a #word in Slack doesn't become a tag, [[a link]] doesn't become a link, and nothing in a message can add HTML, an image or a query to your vault.
  • Saving the same message twice makes nothing new: DFAI recognises it by its channel and time in Slack — even after you've filed or archived the first one — and points at the note you already have. Saving it again later never changes that note, even if the thread has grown.

Paste a Slack link

  • Connect Slack once in Settings (⌘,) → Slack. Make a Slack app at api.slack.com/apps with these user token scopes: channels:history, groups:history, im:history, mpim:history, users:read and users:read.email. Install it to your workspace, copy its User OAuth Token (it starts xoxp-), paste it and press Connect. DFAI asks Slack whose it is and shows Connected as mara in Larkspur Payroll. The token stays in this Mac's Keychain, goes only to slack.com, and is only used to read — DFAI can't post, edit or delete with it. Disconnect forgets it on this Mac.
  • Paste a message link (Slack's Copy link on a message) into a note or into quick capture (⇧⌘N). The link is pasted as usual, and a card offers the message: who wrote it, its words, and how many replies and files its thread has. Save as task or Save as note puts it in Inbox/Captures/ exactly as above — the same note a message sent from Slack would make — and Open takes you to it.
  • Pasting it again says Already in your vault and makes nothing new.
  • When it can't be read, the card says why and what to do, and the link stays as you pasted it: not connected (Open Settings), a token Slack refused or one missing a scope (make a new one), a message that was deleted or is in a conversation you're not in (only the link is kept), or Slack asking DFAI to slow down (try again in the seconds it says).
