Outside data and secrets

A source brings data from outside the vault — a calendar feed, a CSV or JSON file or web address, or someone else's SQLite database — in as ordinary notes.

A source is a note in .atlas/sources (under System in Pages) whose properties say where to read, the format (ics, csv, json or sqlite), which folder to write into, which type the notes are, and which field becomes which property. The DFAI project's own vault has one, Milestones, to copy from.

  • Open the source note and press Refresh. It shows what it Reads, where it Writes to, how often it Refreshes (only when you ask, or every few minutes while the note is open), and what the last refresh did: created, refreshed, kept your text, no longer in the feed.
  • If you've edited a note since, your text is kept; only the fields the source owns are rewritten. A record that has gone from the feed marks its note — it is never deleted.
  • The folder it writes into must already exist.
Where a source may run. A plain public feed, or a file inside the vault, works from a note anywhere. A source that sends a secret, or reads a SQLite file outside the vault, runs only when its note is in .atlas/sources (System → sources in Pages). Anywhere else, Refresh fetches nothing and says This source sends the secret “github”, so it runs only from .atlas/sources. Move the note there (System → sources) to refresh it. — or, for a database, This source reads a database outside the vault, so it runs only from .atlas/sources. Move the note there (System → sources) to refresh it. That's because other tools, like the Local API or a synced folder, can write notes in your pages but not in .atlas.

Secrets (tokens for private feeds)

Some feeds need a key. Keep it in Settings (⌘,) → Secrets, which stores it in your Mac's Keychain — never in the vault — and a source names it rather than holding it: {{secret:github}} in its address or a header, or auth: { secret: github }.

  1. Under the list, fill in the three boxes — the name (e.g. github), the value, and the sites it may be sent to (e.g. api.github.com; several separated by commas) — and press Add. All three are needed.
  2. Each secret in the list says which sources use it and Sent only to … the sites you gave.
  3. Replace… changes the value, Sites… changes where it may go, Delete removes it from the Keychain (it tells you which sources will stop refreshing).

The same list holds the key for Claude by API key: a secret named anthropic, with the site api.anthropic.com. DFAI sends it only to Anthropic's API.

Why a secret can be paused. A source note is just text — something synced in, or a tool using the Local API, could have written it — so the note doesn't get to decide where your key goes. DFAI sends a secret only over https, only to the sites you bound it to, and won't follow a redirect to anywhere else. A secret with no sites (for example one set before this rule arrived) shows Sent nowhere until you choose the sites it is for and is refused until you press Sites… and add them. Adding a site to a key that's already saved asks you in a Mac dialog first.

A secret a source names but this Mac doesn't have shows as not set on this Mac, with Set…. Secrets belong to one vault on one Mac: a vault that's moved or copied to another Mac needs them set again. DFAI never shows a secret's value back, and strikes it out of anything a server echoes.

A SQLite file

  • A source with format: sqlite, a file: and a query: turns the query's rows into notes. The query follows the same read-only rules as SQL on the Query page.
  • The file is opened strictly read-only: DFAI never writes to it or leaves files beside it. A database that's being written to (unfinished changes still pending) or that changes while it's read is refused rather than read wrong — try again later.
  • A file outside the vault must be picked with Choose file… on the source note. That choice counts only on this Mac; elsewhere, choose it again.
