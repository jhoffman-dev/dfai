Skills

A skill is a set of instructions for Claude with a name and a description that says when to use it — the same Agent Skills format Claude Code reads, so a skill written here can be copied there as it is.

Where it is

Sidebar

Skills, in the top list after Templates.

Search

⌘K → Skills.

The page lists every skill with its description. A skill that breaks a rule says so under its name — “2 problems”, then each one, such as “Its folder: A skill’s name is lowercase letters, digits and single hyphens, starting and ending with a letter or digit.” — so a skill another tool wrote wrong is shown, never quietly fixed. Under the skills, Automation prompts lists the prompt notes in .atlas/prompts that automations run; Open opens one as a note. They keep working as they always have.

A skill an automation asks with says so under its description: “Used by Meeting actions” — counting an automation that can't be read for another reason, so long as its skill: is a skill's name.

Make a skill

  1. Press New skill at the top of the page.
  2. Name it: lowercase letters, digits and single hyphens, up to 64 characters — weekly-review, not Weekly Review. It can't hold claude or anthropic, or be a name another skill has in any capitals. The name can't be changed later: to rename a skill, make a new one and delete the old.
  3. Write the Description: what the skill does and when to use it, in plain text — no XML tags such as <example>. The counter beside it, 25/1024, counts characters, an emoji as one.
  4. Write the Instructions in Markdown — up to 20,000 characters.
  5. Press Save. It stays off while anything is wrong, and each problem shows under its field as you type.

DFAI writes the skill as .atlas/skills/weekly-review/SKILL.md: name and description at the top, then the instructions.

Edit a skill

  • Click a skill to open it beside the list, change its description or instructions, and press Save. Only what you changed is written: comments, other keys and the rest of the file stay byte for byte as they were.
  • A skill whose name: says something other than its folder's name says so; saving it puts the folder's name in.
  • If the file changes on disk while it's open — another Mac, Claude Code, an editor — and you haven't typed anything, the editor takes the change in. If you have, it says “This skill changed on disk since it was opened.” with Reload, which drops your typing for what's on disk. A save over a file changed since it was opened is refused, never written over.

Ask Claude to write or improve one

  1. In the skill's editor — or a new skill's — press Ask Claude… and say what you want under What should Claude do?: “make this shorter”, or “draft a skill that summarises meeting notes”. Press Ask, or ⌘↩. It uses the way of reaching Claude and the model chosen in Settings → Claude, as the chat does, and says the same thing the chat would when Claude can't be reached, with the command that fixes it.
  2. Claude is shown the skill as it is in the editor, unsaved typing included, and nothing else — it can't read your notes. A skill over 40,000 characters, twice what one may hold, is too long to show it, and says so: “shorten it first. Claude was not asked.” Stop cancels the ask, and so does opening another skill or New skill.
  3. Its draft shows as a change: the lines of the description and the instructions it would remove, struck through, and add, with long unchanged stretches folded (“3 unchanged lines”). A new skill's draft shows the name it would take.
  4. Accept puts the draft in the editor's fields; nothing is written until you press Save. Discard leaves the editor as it was. Ask again asks once more, with the request as you've since changed it.

A draft is held to the same rules as your own typing: one that breaks them is shown as a problem — “Claude’s draft cannot be used: A skill’s description may be at most 1024 characters.” — and changes nothing. A skill you're editing keeps its name: if Claude's draft renames it, the name is ignored and the draft says so, “Claude named it “meeting-summary”; a skill keeps its folder’s name, so it stays “meeting-notes”.” Asking runs Claude in the app, so it isn't something the local API or MCP can do.

Delete a skill

Delete… asks first, naming everything that goes: “Delete “weekly-review”? Its whole folder goes to the Trash, where it can be got back, with 1 other file: scripts/run.sh — and everything in its subfolders, however deep.” When automations use it, the question says so too: “The automation “Meeting actions” uses it, and will fail until it names another skill or a prompt.” Move to Trash puts the skill's whole folder in the macOS Trash.

Skills are not notes

They aren't in Pages (not even under System), search, the graph or [[ suggestions — the Skills page is where they are. Claude and your other tools can list and read them through the local API and MCP; making, editing and deleting stay in the app.

Use a skill in the chat

Attach a skill to a conversation with Skill by the chat's box, or /name. See Ask with a skill.
