Queries

Ask across several types at once — tasks and projects together — follow a link to the note it points at, and sort, group and sub-group the answer. Build it from dropdowns or write it as text; both edit the same query.

  • Open New query from the + next to Views, or from search (⌘K).
  • The page opens on DFAI query, already listing every note of your first type. SQL, the other option beside it, is the SQL page as before.
  • Edit the query as Builder or Text. In the builder, the query it makes is shown as text above the dropdowns.

The builder

RowDoes
FromThe types to list. Add type adds another; the × on one removes it.
WhereAdd condition, then pick a field, what it should be, and a value. With two or more, Match all or any of these. The not button at the front of a condition turns it round: it lists the notes the condition doesn't match.
SortAdd sort, then a field and ascending or descending. Add more to break ties.
GroupGroup by a field, then by another for sub-groups. Nothing turns it off.
AlsoInclude archived notes, and At most n rows (500 if left blank).
  • Fields are the properties of the types in From, plus Title, Type, Tag, Modified, Path and Progress through its checklist, which every note has. A relation's own fields are offered too, as Project · Status: the status of the task's project.
  • What it should be fits the field: is, is not, contains, starts with, is empty, is not empty; numbers add is less than, is at most and so on; dates read is before, is on or after…
  • The value fits the field too: a select's options, the notes a relation can point at (people for an owner), your tags, ticked or not ticked for a checkbox, and for a date either a date that moves — Today, Yesterday, Tomorrow, A week ago, A week from now, A month from now, Start of this week — or On a day… and a date picker. A count from today written in the text, such as @-30d, is in the list as what it is — 30 days ago. Numbers and words are typed.
  • A pick in the builder runs the query at once.

Switching between builder and text

  • Switch to Text at any time and carry on typing. Switch back and the builder reads the text again.
  • Text you type is kept as you typed it; the builder's own spelling replaces it only when you change something in the builder.
  • The builder shows conditions that are all joined by AND, or all by OR, each plain or NOT. A query that brackets AND with OR, or puts NOT over a group, stays text, and says why: “This query brackets conditions together — AND with OR, or NOT over a group — which the builder cannot show as one list. Edit it as text.” A query with a mistake in it stays text too, with “Fix the query to open it in the builder: …”
  • SHOW has no dropdown; a SHOW you wrote in text is kept when you go back to the builder.
  • LINKS TO this has no dropdown either, so a query with it stays text: “This query says LINKS TO, which the builder has no control for. Edit it as text.” CONNECTED TO this is the same. A condition like people = this goes through the builder unchanged.

Writing it as text

FROM task, project
WHERE status != done AND project.owner = [[Julie]] AND tag = #q3
SORT BY due
GROUP BY project THEN status

FieldsA property of a listed type, or title, type, tag, modified, path, progress (see Checklists and progress). One step through a relation: project.status
  • Keywords can be in any capitals. Typed text runs a moment after you stop typing; ⌘ Return runs it at once.
  • Mistakes are pointed at. Under the text, Line n, column n and what's wrong, with the characters underlined — a type that doesn't exist, a field none of the listed types has, < on a select, a word where a date belongs.
  • != means no value is: a note without the property is listed by status != done. A field with several values (tags, a multi-select, several links, a note's type) matches when any of them does.
  • What a field holds is read as the Today page reads it, the same in a condition, a cell, a sort and a group, and in a type's table:
    • A blank item is no item: status: [next-action, ""] is next-action.
    • A date holds its first real day. Words (due: TBD) or a day no calendar has (2026-02-30) are no date, and a due written as two days is the first of them.
    • A number holds one number: estimate: lots is no number, and nor is estimate: [3, 5].
    • Any other field that holds one value — text, a select, a checkbox — holds it only when it is written as one: status: [next-action, done] (or [[next-action, done]]) is no status. The Today page and the weekly review read it the same way, so a task whose status lists archive among others is shown as open work, not hidden as finished — fix the status to finish it.
    • Through a link too: project.due is the linked project's first day.
    • No value means IS EMPTY, a blank cell, and last in a sort. A multi-select of only blank items is empty and shows nothing.
  • tag = #q3 finds tags written in the text or in tags:, and tags nested under it (#q3/plan).
  • Dates compare by the day as written: 2026-09-30T22:00-05:00 is the 30th.
  • FROM task lists every note whose type names it in any capitals or spacing — type: Task too — and type = task asks the same, and GROUP BY type puts every spelling in one group, named as the vault names the type. So does everywhere DFAI finds notes by type: the sidebar's counts, a type's table, a relation's picker, meetings, the term list, the meeting links and Claude's follow-ups. Two types whose names differ only in capitals (Book and book) can't be told apart that way, so a query naming one is pointed at: “Two types are called book: Book and book. Rename one, so book names one type.”
  • Counting from today. date > @-30d AND date <= @today is the last 30 days, not counting the 30th day back; due >= @today AND due <= @+2w is the next two weeks. Each end needs saying: date > @-30d alone takes everything after that day, next month's too, and due <= @+2w alone takes everything overdue. A count reaches 1000 years at most. @startOfWeek is this week's Monday, as the calendar's weeks start. Months count the way the index counts them: a month on from 31 January is 3 March. The sign is needed — @30d is pointed at.
  • this is the note the query is on. FROM meeting WHERE people = this AND date > @-30d AND date <= @today, asked about Mara Quill's note, lists her meetings in the last 30 days. this compares with a relation, with = or !=, also one step through one. LINKS TO this lists the notes whose text links to it; a note linking to itself doesn't count, as it isn't its own backlink. this is a word of the query now, so a query that used it to mean the word — status = this — is pointed at, with “… To mean the word, quote it: 'this'.” Write 'this' in quotes and it works as before.
  • CONNECTED TO this lists the notes joined to it by any link, either way round: a link in either note's text, or in any property of either — a task whose source cites a line of the meeting, or a meeting that lists the task. After a relation it asks about the notes that relation points at: waiting_on CONNECTED TO this, on a company's page, is what you're waiting on from anyone linked with the company. It is what linked pages use for "the tasks that came from this meeting". LINKS TO this is narrower: links in the other note's text only.
  • A query is on a note when it is a query block in that note, or when Claude or another tool asks it about one (atlas_run_query with a context, below). On the Query page, in a saved view, on a dashboard or in an automation, this is pointed at: “this is the note a query is shown on, and this query is not shown on one.”
  • A relation to several types reaches every field any of them has: with a task's project linking a project or an area, project.steward works even if only areas have a steward, and is empty for a task filed under a project.
  • Only one step through a relation: project.owner.team is refused. A step through a relation never reaches a note in .atlas or a hidden folder: a field read through a link to a template is empty. Notes can't be sorted or grouped by a field that holds several values, such as tag.
  • A query holds 2000 conditions at most, and brackets and NOTs nest 64 deep at most.

The answer

  • Layout: Table, Board or List. The count beside it says how many notes, and (more were left out) when the row limit cut it short.
  • Grouped, a table draws the same grouped rows as a grouped table view: heading rows with counts and totals, sub-groups one step in; click a heading to fold it. On a board the groups are the columns and the sub-groups are lanes across them. A query's answer is for reading: it has no + New, and its cards don't drag — though in a saved view of tasks, each task can be ticked, moved or chosen for today.
  • Groups come in order: a select's options as the type orders them, numbers by size, dates by day, the rest by name — reversed when the query sorts that field descending — and notes with no value last. A relation's groups are named for the note.
  • A checkbox groups into true (ticked) and false, which holds every note not ticked, including those without the box.
  • Click a note to open it.

Keep it

  • Save as view: a name and a layout, then Save view. It is listed under Views in the sidebar, and a saved query view shows the other saved queries as tabs across the top. A blank query can't be saved: “Write a query before saving: FROM task.”
  • A saved query view opens with its query folded to one line — the text as written, beside Edit query — so the answer has the page. Edit query opens the builder or the text under it; Hide query folds it again. Whether you left it open is remembered per view, on this Mac. A view whose query is still empty opens with the builder open.
  • On a saved query view, change the query or the layout and Reset · Save as new view… · Save view appear in a strip above the query, as on any view.
  • Add to dashboard: pick the Dashboard, give it a Title if you like, then Add widget. The widget is an DFAI query that lists the rows in their groups and sub-groups, each folding on its own, with relation groups headed by the note's title.
  • The view's file keeps the query as text, exactly as typed, in its query: property.
  • An automation takes its notes with the same builder or text, under Which notes. There, @today and the other moving dates — counts from today and @startOfWeek too — mean the day the rule runs.

In a note: query blocks

A query can live inside a page — a person's meetings on their page, a project's open tasks on the project.

  • In a note, type / → Query. The block opens at its text; write the query and its answer shows under it a moment after you stop typing. Done puts the text away, Edit query brings it back. A mistake is said in place of the rows — “A meeting has no field called stauts.”
  • this is the note the block is in. On Mara Quill's page, FROM meeting WHERE people = this SORT BY date DESC lists her meetings, and the same block on Tobias Fenn's lists his.
  • A table, unless the first line says layout: list (layout: table works too). Other layouts are pointed at: “A query block shows a table or a list; “board” is neither.”
  • The answer is read-only and live: a note saved here, in another pane or by another app shows up as soon as the index has it. The count says how many notes, with (more were left out) past the row limit. Click a note to open it.
  • In the file it's a fenced code block, so Obsidian shows it as code: 
    ```atlas-query
layout: list
FROM meeting WHERE people = this SORT BY date DESC
```
    Saving the note leaves it byte for byte unless you change its text. A fence written in another editor (backticks or ~~~) is shown the same way.
  • Only a block of the note's own is a query block. Inside a list, quote or callout, or with anything after atlas-query on the fence's line, it stays a code block. Typing ```atlas-query in DFAI makes a code block until the note is opened again; / → Query makes the live one at once.
  • Copy a query block and paste it among another note's blocks and it is the same live block there, its this now that note; pasted into a list, quote or callout it is the code. Pasted as plain text elsewhere, it is the fence.
  • Where a note is only drawn — a feed, a page's picture, a shown block in another note — a query block shows as its code.
