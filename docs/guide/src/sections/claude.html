Claude in DFAI

Ask Claude about your vault without leaving the app. It starts out knowing the page you're on, can search and read everything, and proposes changes you accept — it never writes on its own.

Ask

Ask is where a question starts: a page of its own, like Today. Press ⌘J, or Ask beside Search in the sidebar, and type. Before you ask, it lists your Recent questions (the chats kept in Chats/); pick one to carry it on. ⌘J on Ask takes you back to where you were.

  • Every answer links to the notes it came from. A link shows as a coloured chip: click it to open the note at that block, or ⌘-click for a new tab. A highlight's chip opens in the reader.
  • A paragraph, list item or quote with no link is still shown, marked not cited, and the answer's foot counts them (1 paragraph not cited).
  • Answers are text only: the only links are to your notes and to https:// addresses, which open in your browser. A link whose words don't name its site shows the site beside them.
  • Ask and the chat beside the page are one conversation, kept as a note in Chats/.

Open it

  • Press the spark button in any page's top bar (Claude beside the page (⇧⌘J)), or ⇧⌘J. It opens in the right sidebar, on its Claude tab; the same button, ⇧⌘J or the chat's own × closes the sidebar. With the sidebar already open on another tab, ⇧⌘J switches it to Claude. Not while a dialog is open.
  • What you have open comes along as a chip above the box: a note (its title, properties and text), a view (its first 20 rows), a dashboard (its widgets), or, on the Query page in DFAI query, the query you're writing and its first rows. The × on the chip (Leave this out) drops it.
  • Nothing needs turning on first: the chat doesn't use the Local API, only the way to Claude chosen in Settings → Claude.

Ask

  • Type in Ask Claude… and press Return (⇧ Return for a new line). The answer streams in; Stop ends it.
  • Under an answer, Copy copies it; under the latest one, Retry asks again.
  • Answers are drawn as on Ask: each link to a note is a coloured chip that opens the note at that block (⌘-click for a new tab), a paragraph, list item or quote with no link is marked not cited, and the answer's foot counts them (1 paragraph not cited). Long titles and words wrap to the sidebar's width.

Ask with a skill

  • Press Skill by the box (Use a skill) and pick one of your skills, or type / and the start of its name and pick it from the list. You can also type /weekly-review and your question after it, like /weekly-review What did I finish?, and press Return. The skill shows as a chip above the box; its × (Ask without this skill) takes it off. While the list shows, ↓ and ↑ move through it from the box, Return picks the one marked, and Esc closes it; a screen reader hears how many skills match. A /word that isn't one of your skills — or any /word while the skills can't be read — is sent as you typed it. A /name question shows at once and holds the chat until it's asked, so nothing sent meanwhile overtakes it; Stop ends the wait at once, and the question stays as you typed it, for Retry. While the skills are still being read, the list says Reading skills… and Return waits rather than send what you typed.
  • Each question you ask while the chip is there is asked with the skill's instructions, read again each time, so an edit on the Skills page counts from the next question. Claude follows them within DFAI's own rules: its tools still only read, and a change is still a proposal you accept.
  • Only you attach a skill. Claude isn't shown your skills to pick from, and nothing in a note or a tool's answer can bring one in.
  • A skill that's gone, has a problem the Skills page shows, or is longer than 20,000 characters counting an emoji as two — the same limit as an automation — isn't asked with. The chip says why, like “The skill weekly-review cannot be used: Its instructions are 20001 characters as Claude is handed them, an emoji counting as two; a prompt may be at most 20000.”, and the question waits with Retry until you fix the skill or take the chip off. Claude isn't asked.
  • The chat's note says which skill each answer used: “Used the skill weekly-review”.
  • A skill stays with the conversation you attached it to. New chat starts without one, and a past chat you open again doesn't bring its skill back — attach it again if you want it.
  • Ask and the chat beside the page share the chip, as they share the conversation.

What Claude can do

  • Search and read everything with the same read-only tools a connected Claude has over MCP: notes, types, backlinks, views, dashboards, queries, calendars, tags and the Archive. Each call shows in the conversation as a line, like Searched for “…” or Ran the query “…”.
  • Archived notes come only when you ask about them.
  • Never a whole huge folder. Every list of notes it reads — here or through an MCP client — is a page of at most 500, with the total and a cursor for the next page. Backlinks are paged too.
  • Ask about a day — “what did today's meetings say?” — and it lists that day's notes: those named for it, like Meetings/2026/10/2026-10-14 Larkspur Standup.md, and those whose date is that day. Search finds a note by the words of its title first, and by the day in its file name. If Claude asks for a note that isn't there, it's told the real notes with a name like it, so it never has to guess where one is filed.
  • It can't run automations, refresh sources or reach the web, and nothing it reads is changed.
  • It can draft for you, as proposals: the tasks of a meeting (below) and a dashboard or a view (below). Those wait in the Inbox until you answer them.

Drafting tasks from a meeting

Ask “pull the tasks out of today's Larkspur Payroll sync” and Claude runs the same reading the meeting extraction automation does, on that one meeting, now. You don't need the automation turned on.

  • The conversation shows Drafted the tasks of Meetings/2026-10-14 Larkspur Payroll sync.md as proposals. Each item — yours, a waiting-for on someone else, a decision, a follow-up — is a proposal in the Inbox, citing the turn it came from, exactly as the automation's are. Nothing else is written: no task is made and the meeting isn't touched until you accept.
  • Ask again and nothing is proposed twice — not what you already accepted or rejected, and not what the automation already proposed for that meeting. If the meeting's words haven't changed since Claude drafted it, Claude isn't asked again at all; once they change (a corrected transcript, say), it reads the meeting afresh.
  • It asks Claude as your Claude steps do, with the provider and model in Settings → Claude. A long meeting takes a while: if Claude is still reading after about 25 seconds, the conversation says it's still running, and the proposals turn up in the Inbox when it's done. If it fails then — Claude stopped, or you deleted the meeting or opened another vault meanwhile — DFAI says so in a notice and in Activity, naming the meeting, and nothing is written.
  • A note that isn't a meeting is refused: Tasks/Send it.md is not a meeting note.
  • A connected Claude can do the same with atlas_propose_tasks.

Asking for a dashboard

Ask “build me a dashboard of my tasks by status” — or a saved view, “a board of open tasks” — and Claude describes it and DFAI checks it the way the widget editor and the New view dialog check yours. A dashboard lives in .atlas/dashboards, which nothing outside the app writes, so what Claude makes is a proposal:

  1. The conversation shows Proposed the dashboard “Task board”, and the Inbox has a Dashboard card listing each widget — its kind and title — and saying Accepting makes it in .atlas/dashboards. A view's card says its type and layout.
  2. Accept writes the dashboard and it appears under Dashboards in the sidebar. A dashboard of that name already there is left alone: the new one is Task board 2. Edit lets you rename it first. Undo takes it back out.
  3. Reject writes nothing.
  • A dashboard that wouldn't draw is never proposed. If a widget counts a type your vault doesn't have, or a chart has nothing to group by, Claude is told exactly what the editor would tell you — widgets[1]: A bar chart needs a property to group by. — and fixes it before proposing. Accept checks again, in case you deleted a type since.
  • Read a query before you accept it. The card shows each widget's filters (status is inbox), and a widget that runs SQL or a DFAI query shows it whole, in monospace — what you'd be accepting is exactly what's written.
  • No loose reading. A filter DFAI can't read, a width that isn't a whole number of columns, an icon or chart style that doesn't exist, or a name with invisible characters is refused and Claude told why — never quietly dropped, which could make a tile count every note.
  • The same dashboard asked for twice is proposed once, and Claude is told what became of the first: still waiting, or accepted or rejected and when.
  • A connected Claude can propose one with atlas_make_dashboard, but only Accept here in DFAI makes it: atlas_accept_proposal refuses a dashboard or view proposal.

Changes you accept

When you ask for a change, Claude proposes it as a card — Proposed edit or Proposed new note — showing the full vault path it would write, any property changes, and the text as the note would show it: removed blocks struck through, added ones marked, unchanged runs folded (3 unchanged blocks).

  1. Nothing is written until you press Accept; Reject drops it. The buttons grey out while it writes, so one Accept is one write.
  2. Accept writes exactly what the card showed, at exactly that path.
  3. Undo on an accepted card puts the note back as it was, if nothing has written it since.

A chat's cards live in the chat. What Claude proposes while you're away waits as a note in the Inbox instead, answered the same way.

When Accept refuses. If the note changed after the proposal, the card says <note> changed since this was proposed; nothing was written. If it's open with typing not yet saved: <note> has unsaved typing; save it first, so nothing you typed is written over. Nothing can be proposed into .atlas, any other hidden folder, or Chats/. A tool call Claude shows inside a code block is shown as an example, not run.
  • Cards sit in the conversation, which scrolls on its own; the window doesn't.
  • If a proposal can't be made, the conversation says so, with the reason: Could not propose an edit to <path> or Could not propose a new note, “<title>”. The chat's note keeps it as a line: > Could not propose an edit to X: <reason>.
  • A chat reopened from Past chats shows its past proposals as lines only, with no card. To get a card, ask again.

Chats

  • Each chat is saved as a note in Chats/, named from the first words you asked. After the first turn DFAI only adds to it, so anything you edit in an old chat is kept.
  • Past chats in the pane's header lists them and reopens one; New chat starts over.
  • If a past chat's note is gone (deleted or moved since the list was read), picking it says That chat could not be opened: … and the list is read again, so the row goes. A list that can't be read says Past chats could not be read: ….
  • While an answer is still arriving, the Past chats rows are greyed out (Wait for the answer to finish); press Stop or let it finish first.
  • If a chat can't be saved, the pane says The chat could not be saved to Chats/: … and the reason.

Your name (Settings → Profile)

Settings (⌘,) → Profile has two fields: Full name, the way you want it written, and Preferred name — What you go by, if it is not your first name. Press Return or leave the field to save it; Esc puts back what it held.

  • The name is kept in this vault's settings (.atlas/settings.md), not on this Mac, so every Mac that syncs the vault has it. Set it once.
  • Clearing a field removes the name; it isn't saved as a blank. Changing one leaves the other as the file holds it.
  • Invisible characters (zero-width spaces, direction marks and the like) and line breaks are dropped, and a name is cut at 100 characters, never halfway through an emoji or a flag.
  • Until the vault's settings have been read, both fields are greyed out and the line under Full name says Not read yet: Claude asks for your name. With no full name it says Not set: Claude writes “[Your name]” rather than guess one; with one, What Claude writes for you. If the name can't be read or saved, the reason shows under the fields.

What Claude does with it:

  • A full name is set: Claude uses exactly that name wherever a note needs yours — an owner, author, assignee, attendee or signature — never another spelling of it.
  • No full name: it writes [Your name] there, or asks you. A preferred name alone isn't enough for this.
  • DFAI can't read the name yet (the settings aren't read, or can't be): it asks you rather than writing [Your name], since you may well have set one.
  • It never guesses a name — not from your username, an email address, a folder path or anything else. A name set mid-chat counts from the next question.

While no full name is set — even if a preferred name is — an empty chat says Claude doesn’t know your name, so where a note needs it, it writes “[Your name]” rather than guess., with a Set your name button that opens Settings.

Your emails (Settings → Profile)

Under your name, Your emails holds the addresses that are you in a meeting. DFAI knows you by these as well as by your name: an attendee at one of them is you — never proposed as someone new — so are the action items they take on, and in a Granola meeting you own, “me” is written as You. DFAI never makes one up: not from your name, your username or a folder path.

  • Type them; they save as you go. There's no Save button: what you type is saved once you pause, and when you leave the field (or close Settings), and the line under it says Saved — or Couldn’t save: … with why. The field takes several lines: one address on each line, or separated with commas or semicolons. A pasted Mara Quill <mara.quill@example.com> or "Quill, Mara" <mara.quill@example.com> keeps just the address (the name may sit on the line above it), and addresses are kept in lower case. If something you typed isn't an address — a stray word, or an invisible character a copy brought with it — the card names it and saves nothing until you fix it. If the save itself fails, what you typed stays in the field and the reason shows under it; leave the field again to try again. More than 10 KB of text is refused without being read.
  • Accents and international domains match however they arrive. rén@example.com typed with a separate accent, or mara@bücher.example sent as mara@xn--bcher-kva.example, is the same address.
  • Until you save some, the addresses on your own Person note — the one your full name names — are you, everywhere DFAI asks: linking, whose an action item is, and a Granola meeting's “me”. The field shows them with In use from your Person note; nothing needs pressing for them to count. Once you save addresses here (or while granola_self_emails holds some), only those count.
  • They're kept in the vault's settings (selfEmails in .atlas/settings.md), beside your name, so every Mac that syncs the vault has them. Emptying the field removes the setting, and your Person note's addresses are used again.
  • Set them in Settings → Granola before? Those (granola_self_emails) are still used while selfEmails is empty, and the field shows them with In use from granola_self_emails. Edit them here to move them: the same save writes selfEmails and removes granola_self_emails. Empty the field to remove them both.
  • An address here is you even if it looks like a group (team@…): DFAI takes your word for it, links you, and never reads that attendee as a group.
  • With none set, and no Person note of yours, DFAI knows you by your name alone.
  • If n8n maps Granola meetings too, change the addresses in both places: here, and selfEmails in the OPTIONS of the n8n Code node that maps them (tools/n8n). Both must hold the same addresses, or the same meeting is written two ways and becomes a sync conflict copy. Nothing checks this for you.

Set it up (Settings → Claude)

Settings (⌘,) → Claude → Reach Claude through: Claude Code (the default) or API key. The line under it says Ready, or what's wrong and the command that fixes it. The choice is kept on this Mac, not in the vault.

Claude Code

Runs through the Claude Code you installed and logged into, so DFAI never sees your login. It runs locked down: none of Claude Code's own tools, no settings, hooks or MCP servers, started away from any project, and only from where Claude Code installs.

API key

An Anthropic API key kept as a secret named anthropic, bound to api.anthropic.com; then choose API key here. Answers arrive whole rather than word by word.

If Claude Code isn't installed: Claude Code is not installed on this Mac, or not where DFAI looks for it. Install it with

curl -fsSL https://claude.ai/install.sh | bash

If it isn't logged in: Claude Code is installed but not logged in. Log in with

claude auth login

The chat pane shows the same message and command, with its own copy button. With an API key and none set: No Anthropic API key is set for this vault. — or, if the secret goes elsewhere, The "anthropic" secret is not bound to api.anthropic.com.

  • Time limits. Checking Claude Code gets 15 seconds (Claude Code did not say whether it is logged in within 15 seconds.); each round of an answer gets 10 minutes (Claude Code did not finish within 10 minutes.).
  • Model. Blank means claude-opus-5-5; type another model's name in Model to use it. The pane's header shows which.
