Where notes live

Every type has a home folder. A new note of a type goes there, whatever note is open. What it's filed under is a link, not a folder.

  • Change a home with folder: in the type's file in .atlas/types — folder: Work/Tasks/{YYYY}. {YYYY} and {MM} come from the note's own date, else a date its file name starts with, else today. A blank folder: means no home: its notes go where they always did.
  • A folder DFAI can't use — an unknown token, outside the vault, in .atlas, hidden, the Archive, too deep — is ignored, not refused.
  • Every way of making a typed note uses it: a template, a view's + New or a board card, New <type>… in a relation, a type's table, Make task on a checklist line, a task from a meeting's action item or an accepted proposal, quick add through the API and MCP, and POST /v1/notes with no folder. A decision has no home and goes at the top.
  • A folder you choose wins. New note here on a folder puts it there; quick capture (⇧⌘N) puts it in the Inbox. A plain note with no type still goes beside the note you're on, or at the top.

Tidy the vault, once

A vault from before home folders is offered a tidy on the Inbox page: “Every type has a home folder now. 212 notes could move to theirs, out of the root of the vault and the old Inbox/Meetings.”

  1. Press Preview the tidy. Nothing is written yet.
  2. Check the list: each note, Now → Moves to. Under Left where they are, each note that stays and why — its home already has a note by that name; two notes would land on the same path (refused, never renamed: rename one first); or a meeting the import hasn't let in yet.
  3. Press Move N notes, or Cancel. It moves notes loose at the top of the vault to their homes, and imported meetings from Inbox/Meetings to their months, rewriting links so every link and relation opens the same note.
  • Activity gets “Tidied the vault: moved 212 notes to their home folders”, and a warning for each note left as it was.
  • Running it again moves nothing. Not now hides it until the vault is opened again.
