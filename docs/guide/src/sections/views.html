Views

A view is a saved way of looking at notes of one type, and a type owns its views. Click a type in the sidebar and its views open as tabs across the top. To look across several types at once, save a query as a view.

A type's views, as tabs

  • Click a type in the sidebar and you see only that type's views, as tabs. It opens on the tab you last had for that type on this Mac, else the first.
  • Opening a view any other way — a link, search, the Views section — lands on the same page, with that tab selected.
  • A type with no views yet shows one default table tab, named for the type (Idea table), with every property as a column. It is only written as a view once you add a view beside it, rename it or duplicate it. It can't be deleted — there's nothing to delete.

Add, rename, copy and delete from the tabs

  • + at the end of the tabs (Add a view) lists the layouts; pick one. The view is named for you, like Task board or Task list (then Task list 2), and opens selected.
  • The … on the selected tab (View options) has:
    • Rename — type the new name in the tab and press Return. It changes the tab's name only; you never need to know the view's file name, and links to it keep working.
    • Duplicate — a full copy, with its filter, sort and grouping, named … copy (Board copy, then Board copy 2).
    • Delete view — asks first, then Move to Trash. You land on the next tab, or the previous one if it was last.
  • Settings are edited in place: Layout, Filter, Sort, Group and Properties in the toolbar, as below.

Reorder the tabs

  • Drag a tab to a new place, or focus it and press Alt+← / Alt+→ to move it one place.
  • The order is saved in the views themselves, so it syncs to your other Macs.
  • Views nobody has reordered keep the old order (by layout, then name), and nothing is rewritten until you change the tabs.

Query views, SQL views and dashboards are unchanged: they belong to no one type, so they keep their own pages and their places under Views and Dashboards.

Make and change views

  • New view: the + on a type's tabs (above), or the + next to Views in the sidebar — pick a name, the type and a layout. That sidebar + also has New query, for a view across types — see Queries.
  • Layout, Filter, Sort, Group and Properties (which fields show) change the view at once. Grouping is below.
  • While it differs from what's saved, a bar above the toolbar says This view has unsaved changes. with Reset (back to what's saved), Save as new view… (name the copy, then Save) and Save view. Editing cells, dragging cards and ticking tasks save straight away.
  • Include archived lists archived notes too, for now. It isn't saved with the view and turns off when you go to another view.

Filter

  • Filter → pick a property and a condition (is, is not, contains, …), then a value. The view redraws at once; Save view keeps it.
  • The value box offers what the property can hold: a status's or select's options (a task's eight GTD statuses), the vault's tags for tags, true and false for a checkbox, Today, Tomorrow and the like for a date, plus a date picker. For a relation, start typing and it lists the notes it can point at.
  • From the keyboard: ↓ ↑ to move through the list, Enter to pick, Enter again to add the filter. Esc closes the list.
  • Type the value as the table shows it: Next Action, next action and next-action are the same status. Anything else is kept as typed, except on a checkbox, which takes only true or false.
  • To leave out several values, add one is not for each: Status is not Archive and Status is not Someday.
  • On a property that holds several values — tags, a multi-select, a relation to several notes — is compares the whole list, so it matches only a note with just that one value. Use contains there.

Group and sub-group

  • Group in the toolbar has Group by, then Then by to split each group again. It works on tables and boards: on a table they're groups and sub-groups, on a board they're columns and lanes.
  • None turns a grouping off. A board always has columns, so its Group by has no None; its Then by does.
  • A property that can hold several values — a multi-select, a relation that allows many — is listed but can't be picked, with the reason: “A note can have several of labels, so it cannot be grouped by it.”
  • Groups come in order: a select's options as the type orders them, numbers by size, dates by day, the rest by name — reversed when the view sorts that property descending. Notes with no value gather under No value, last.
  • A checkbox groups into true (ticked) and false, which holds every note not ticked, including those without the box.

Tables

  • Compact rows. Each note is one short row, named by its title; click the name to peek it — ⌘-click opens it in a new tab, ⌘⇧-click beside. Empty cells are left blank, and statuses show as pills.
  • The header stays put. The column names stay at the top as you scroll, as plain words with no icons; an arrow marks the column the table is sorted by.
  • Long values are cut short with …; hover the cell for the whole value. A relation's names stay on one line the same way, and hovering lists them all.
  • The footer has New <type>, then how many notes — 186 tasks, with (more were left out) past the row limit — then, grouped, how many in each group (174 done, 10 backlog, 2 Larkspur Payroll), and how the table is arranged: Grouped by status · sorted by phase, then due (descending).
  • From the keyboard: Tab to a row's name, then ↓ ↑ move a row (group headings are stops too), Home End go to the first and last, and Page Down Page Up move a window's worth at a time.

Editing in place

  • Click a cell, or press Return on it, to edit it without opening the note. The cell wears a ring while you edit it. Return saves, Esc puts it back as it was, and Tab / ⇧Tab save and move to the next or previous cell, then on to the next row.
  • Each kind gets its own editor. A status or select opens a picker under the cell: type to filter, ↓ ↑ and Return, or press an option's number — 3 picks the third. A multi-select opens the same picker with every value it holds ticked: a click, Return or a number toggles one, saved at once, and the picker stays open for the next. A relation opens the notes it can link with the search field focused — type to narrow them, with Create <type> ‘…’ to make one; × on a chip unlinks just that one. If the notes to link can't be read, the picker says so instead of showing an empty list; open it again to retry. A date takes a day, a number refuses letters, and a box ticks on a click or Space.
  • It saves straight away, one write per edit, to that note's file — only the property you changed; the rest of the file stays exactly as it was. The table shows the new value at once, before the index catches up.
  • A cell that changed while you edited it — in another pane or another app — isn't written over: the edit is refused, the line above the table says This cell changed while it was being edited, so the edit was not written. Try again., and the cell shows what the file now holds. A write that fails is said in the same place.
  • A picker is one overlay among the rest. Opening search (⌘K) or another menu over it closes it without saving anything; Esc closes it and leaves you on the cell. Scroll its row out of view and it closes too, without saving.
  • Setting a task's status to its done option finishes it as ticking it does: a repeating task rolls on to its next date.
  • Not yet: a type with no views of its own shows a plain table on its page, whose cells still edit as text. Add a view to the type to get these editors.

Grouped tables

  • Each group gets a heading row across the table: an arrow, a status dot for a status or select option, the group's value, and how many notes. Sub-groups sit one step in, with headings of their own.
  • Every row of a group is listed, however many: a long group scrolls rather than stopping at Show more.
  • The heading row shows totals under the columns: a number column's sum, and for a checkbox how many are ticked (2 checked).
  • Click a heading to fold the group shut or open it again. Folds are remembered per view, on this Mac.
  • + New at the foot of a group adds a note already in it: it gets the group's value, and the sub-group's (a number as a number; the ticked group ticks the box). No value and the unticked group give it nothing.
  • A table switched from a board keeps the board's grouping, so its columns become groups.

Boards

  • Equal columns. The columns share the width equally, empty or not. When that would make them too narrow, the board scrolls sideways instead.
  • Each column's head shows a status dot, the label and how many cards, with a + at the right to add a card to that column. The No value column, and a column that is no status, has no dot.
  • A card shows its title (up to two lines), a line of its summary, how far through its checklist it is, and one line of its other properties — Phase 14 · Bug fixer · 1h. The column's property is left out, since the column says it, and so is anything empty. A card in the finished column shows a tick, or its done box ticked.
  • A long column shows its first cards and N more; open it and Show fewer folds it back. An empty column says No tasks.
  • Drag a card and the column (or lane cell) under it lights with a ring, so you see where it will land.

Board lanes

  • With Then by set, the board splits into lanes running across all the columns, one per value, each with a heading, a count and an arrow to fold it.
  • Drag a card to any cell — another column, another lane, or both. Both properties change together, as one ⌘Z. Dropping in a No value column or lane takes that property off the note. A number column writes a number and a checkbox column ticks or unticks the box, never text. From the keyboard: Space to pick a card up, arrows to move it across columns and up and down lanes, Space to drop.
  • Each cell shows its first cards and N more, like a column, and has its own + New that fills in both values.
  • A card's line of properties leaves out the lane's property too; the lane already says it.
  • Dragging a task into its finished status — Archive for a GTD task — finishes it, whether that is a column or a lane. When the type has a status, only that status counts — the last column of some other property is just a column. A repeating task rolls on to its next date once, and the other property you dropped it into is kept.

Act on several rows

  1. In a table view, press Select. Each row gets a checkbox; the one in the heading ticks them all.
  2. Tick the notes. Shift-click a second box — or ⇧ Space on it — to take every row between, in the order the table shows them, across its groups and down past the rows you have scrolled by. Rows in a folded group are left out. A bar says how many are selected.
  3. Press Archive N notes — or, for archived rows shown with Include archived, Unarchive N notes. One batch runs at a time; any note that couldn't go stays ticked. Export N notes… on the same bar exports them together — see Exporting notes.

Leaving select mode, or the view, clears the ticks.
